# 發布後 App 內更新驗收：0.14.2 → 0.15.1

2026-11-12，依使用者要求驗證上一個發布版更新至最新版。結果：**MuMu API32 通過；API35 在系統確認視窗前受阻，未通過。** 本輪沒有重跑遊戲顯示功能。

## 流程與環境

只操作既有隔離 index4／5；先保存透視鏡自有資料，再以原簽章官方 0.14.2/code53、標準 PM 降版保留 UID／設定。這是測試起點準備，不算 App 更新能力。其後查詢、下載、核對與要求安裝均由普通 App 操作，ADB 為 shell UID2000；不以 root 或 ADB 代替待驗安裝流程。

0.14.2 取自公開發布頁，SHA256 `799d3aef43930385611cabe84657c70738990943f2e24df1cea8a82d184213b8`。查詢使用正式 main 預覽索引，下載正式發布的 0.15.1/code55。兩台 App 下載檔，以及 API32 安裝後讀回 base APK，SHA256 均為 `a4d2e1578b344d0bdef0e89a0ce5a6664f3ba380e682ad7ccc463f5ef67f3bed`。

## API35 已知問題

系統對 `dev.ody.seedpreview.INSTALL_RESULT.<session>` 回呼記錄 `Background activity launch blocked`／`BAL_BLOCK`、`balRequireOptInByPendingIntentCreator: true`，當時 App 在前景仍未顯示安裝確認。不是下載失敗、雜湊不符或 Root 命名空間問題。

0.14.2 的 `LensUpdateInstaller` 建立 Activity PendingIntent 時未帶 creator 背景啟動選項，Android 15／target35 不再預設授予此能力，與[官方規則](https://developer.android.com/guide/components/activities/background-starts)相符。0.15.1 沿用同一段安裝程式碼，**不能宣稱已修正未來更新**。修正必須另升版本並驗證；不能重發相同版本 APK，也不能藉由目標 APK 或公開索引修改已安裝舊版的回呼行為。

API35 先在 App 按取消，確認原版本及設定保留；再用 ADB 維護方式覆蓋回公開0.15.1並開啟確認，這一步只恢復測試機，明確不計入 App 內更新通過。最後透過 App 關閉全部，還原安裝來源許可。原始失敗證據沒有清除。
