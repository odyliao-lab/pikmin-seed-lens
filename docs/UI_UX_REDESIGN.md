## 現況與優先改善

審視來源為 `app/src/dev/ody/seedpreview/MainActivity.java` 及本專案既存私人 0.5.2 介面證據；沒有為本輪設計操作裝置或擷取登入畫面。

| 現況 | 使用影響 | 改版方式 |
|---|---|---|
| 長說明、兩項同意、三個按鈕與狀態垂直排列 | 第一次開啟難以辨認當前狀態與主要操作 | 首頁先呈現狀態及一個主要入口；同意與前置條件置於啟用流程 |
| 啟用、OFF、重查三個按鈕視覺權重相同 | 不容易判斷下一步；容易把重查當重試 | 主操作使用森林綠；OFF 與只讀重查保留清楚文字及次要層級 |
| 工程輸出直接作為主要狀態文字 | 不了解卡片等待、拒絕與結果不明的差異 | 顯示可理解的狀態與下一步；原始結果收在進階診斷 |
| 無獨立功能入口與設定架構 | 後續功能容易累積成更長的首頁 | 建立首頁／工具／設定的結構；目前工具只列實際存在的花苗透視 |
| 原生垂直容器使用固定像素 padding，沒有捲動容器 | 小螢幕、橫向與大字級可能擠壓操作空間 | Android 實作使用 dp／sp、安全區、可捲動內容與自適應文字 |

## 視覺方向

使用者已選定「森林手帳」：暖米白背景、深森林綠操作色、少量放大鏡金色、柔和圓角與清楚留白。
皮克敏插畫置於首頁品牌區，不把文字覆在複雜的圖片上，也不以角色顏色承擔成功／錯誤語意。
使用者提供的原圖在互動稿中保持原檔位元組，僅以版面裁切呈現；原圖不提交 Git。

「輕量工具」保留為前一輪比較方案，不再作為本輪採用版型。首頁保留品牌圖，工具頁直接操作功能，不需越過插畫或進入內頁才能切換。

淺／深色各有獨立表面與文字配色；角色圖只在首頁出現，不覆蓋確認、拒絕與故障處理。

## 導覽與擴充

- **首頁**：品牌圖、目前顯示狀態、準備啟用、OFF 還原、只讀核對與新手說明。
- **工具**：每項功能一列，顯示圖示、名稱、簡短說明與右側開關；不做進入內頁的箭頭或先導航再切換。目前僅花苗名稱透視，不先放無作用的預告按鈕。
- **設定**：外觀、操作說明、版本／相容性與進階診斷。系統及精確遊戲版本資訊不是相容成功的替代證據。

依使用者本輪要求，保留「工具」分頁，作為現在與未來功能的直接開關清單；首頁、工具與設定三分頁沿用森林手帳風格。

### 工具開關的操作規則

- 開啟花苗透視時，在同一列下方展開當次必要確認，不導航到下一層。確認後執行既有流程；取消或切換分頁清除兩項同意。
- 關閉時，直接提出 OFF 並等待確定回報，不跳轉、不再次要求啟用同意。進行中鎖住開關，不能中斷原交易或重送。
- 開關旁必須有文字狀態。尚未核對不稱為 OFF；確認尚未完成時不能先把開關當作已啟用。
- 控制 ON 已確定但卡片／畫面尚待確認時，可顯示開關已開，同時明示「啟用要求已送出，等待卡片，顯示待確認」；不是宣稱畫面成功。
- UNKNOWN 顯示「結果不明，不代表已關閉」，停用啟用開關；未知記錄不因點擊或分頁切換清除。不支援同樣停用並顯示原因。
- 未來各功能的開關各自綁定實際控制狀態，不能只存一個偏好值，就顯示功能已執行成功。

新工具採資料描述（穩定 ID、標題、圖示、說明、入口、支援條件）註冊到導覽，實際執行與狀態保持各自控制器。
不要把所有功能按鈕堆入 MainActivity；不為美化引入網路權限、背景服務、掃描器管理、GPS、庫存寫入或遊戲 RPC。
顯示偏好只影響介面，不能作為 Root、主畫面確認或停止遊戲的授權。

## 啟用流程與狀態契約

首頁的「準備啟用」導向工具頁同一功能的行內確認；工具頁開關直接展開該確認，不另開功能內頁。展開本身不執行載入。
使用者需分別確認已登入主畫面／其他操作暫停，以及同意載入逾時或結果不明時停止該次遊戲。
第一項仍須真正核對唯一 PID／start；按下啟用前再核對，交給既有 guarded native 交易。
兩項勾選不可預設、不可持久保存；離開 App、切換分頁、取消行內確認、程序改變或使用一次後失效。

| 真實來源狀態 | 主要介面 | 可做的操作／限制 |
|---|---|---|
| 尚未讀取或資料過期 | 尚未核對／準備好再出發 | 不以預設 OFF 宣稱已還原；允許只讀核對或準備啟用 |
| 正在核對／載入／關閉 | 正在處理，請等候 | 維持既有單一操作與 native lease；所有會啟動新操作的入口鎖住 |
| 已送出啟用但 waiting-cards／尚無新鮮 ready | 等待開啟列表，顯示待確認 | 不顯示「成功」；不自動再次載入 |
| 同 PID／start 的新鮮 renderer 與控制 ON | 已啟用 | 只表示當次執行狀態；不代表兩頁、縮字、捲動或平台驗收已通過 |
| OFF 已有確定回報 | 顯示已關閉 | 關閉還原顯示，不稱為卸載程式庫；畫面還原仍需實測 |
| 呼叫 UNKNOWN／不完整記錄 | 結果不明，已鎖住重新啟用 | 保留原紀錄、不補成功、不自動重送；先由使用者重開遊戲再重新確認 |
| 不支援的平台或未知遊戲版本 | 暫不支援，保持原顯示 | 說明可理解的原因；不得提供忽略檢查／強制啟用入口 |

UNKNOWN 不應單憑畫面按鈕清除，也不能將一般讀取錯誤都歸類成同一個故障。
OFF 可依原設計獨立提出，但遵守交易鎖；不能為了讓按鈕看似立即生效而中斷載入、釋放 lease 或把 UNKNOWN 改成還原成功。
確切 version／code／digest／prologue／runtime metadata、Root `su -M`、NativeBridge 准入與 append-only 歷史原樣保留。

互動稿的情境為示意資料，不連接裝置。勾選只模擬核對，啟用只進入等待卡片；不會自動推進到成功。
設計控制可預覽 OFF、等待卡片、ON、UNKNOWN 與不支援，不構成實機證據。

## Android 實作順序與驗收

1. 先抽離呈現模型及狀態轉譯，沿用原執行入口、同意範圍與全部守門。無法明確解析的輸出顯示未確認，保留原文診斷，不以子字串猜測成功。
2. 加入可捲動介面、dp／sp、色彩與字級資源、主狀態區，以及工具清單開關／行內確認。狀態由來源驅動，不把視覺切換當控制切換。
3. 引入首頁圖、外觀偏好與三分頁導覽。圖片離線打包，適當尺寸的衍生素材另建置，原件保留，不隨網路載入。
4. 驗證 320dp、窄高與橫向、大字級／顯示縮放、鍵盤焦點、深色、狀態文字換行，以及至少 48dp 的 Android 操作目標。選擇與故障均須文字識別，不能只靠色彩。TalkBack為額外選配研究，不作本輪交付門檻。
5. 檢查首次啟用、未同意拒絕、離開再返回需重勾、遊戲程序更換、只讀重查、進行中鎖定、等待卡片、UNKNOWN、拒絕與 OFF。只對真正變更的狀態層增加有意義測試。
6. 新交付 APK 必須新 version/code、原簽章，先在指定隔離環境回歸兩頁名稱、長字、真離屏重用、OFF 及遊戲重啟。不同 Android／ABI／遊戲版本資格不得因 UI 改版互相轉記。

本輪互動稿的瀏覽器檢查與 Android／遊戲驗收分開記錄；既有相容性矩陣保持不變。
