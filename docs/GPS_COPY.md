# 複製探險座標

0.13.3/code49 開發候選，在四組顯示下方新增獨立開關，預設關閉、說明收合。開啟後，進入花苗／水果探險詳情，或左右換卡並停穩約 0.4 秒，將目前選取項目的座標複製到本機剪貼簿。四組顯示全部關閉時仍可使用；「關閉全部」也涵蓋此開關。

沿用原本 Root＋單一 APK 自包含載入及新 PID 綁定，不需額外安裝套件、模組、電腦注入或複製檔案。此候選僅開放既有精確 Game157.0/code1793360009、MuMu API32／35 x86_64＋NativeBridge 資格；沒有放寬版本或載入守門。

## 行為與保護

- 只讀目前遊戲資料，不移動定位、不派遣或領取，不改物品。
- 要求單一 focused 且 active 詳情頁、相同 session／項目／頁面，複製前再核對。
- 同一項目成功後不重複複製；換卡、OFF／ON 或新 session 才重新判定。失敗最多三次，避免每幀重試。
- 弱參考頁面上限八個；缺身分、非法座標、能力不符或不唯一就停止，不沿用舊座標。
- JNI 寫入後讀回完全一致才記為成功；不依賴系統 Toast。App 顯示「本次遊戲」累計，不能當成目前卡片的獨立證據。
- OFF 停止寫入，不清除或還原使用者剪貼簿。座標不寫檔、不進診斷 JSON、不上傳。
- 自有 `seed-lens-gps-copy.txt`、`seed_lens_gps_copy_status.tsv`；不讀取其他 App 的設定、SO 或服務。
- 設定讀取失敗保持未知；新設定缺檔才初始化 OFF。關閉全部先保存 App pending-OFF，再由原生交易寫入。

## 分層驗證

| 層級 | 結果與界線 |
|---|---|
| 離線 | GPS 設定／新鮮度／不同 PID／非成功回報十項；真實 controller 排程與持久 OFF 44 項；含查詢中仍可排隊保存 GPS 意願 |
| 原生策略 | 400ms、A→B→A、去重、session、三次失敗上限、非法座標；x86_64 策略與檔案交易測試於隔離 API32 實際執行 |
| 平台 probe | API32／35 JNI 主執行緒與 detached worker copy/readback、OFF／非法輸入通過。probe 不是產品依賴，產品執行前移除 |
| API32 遊戲 | 0.13.3、精確157.0：原四組 OFF、GPS 獨立啟用、水果詳情複製、OFF 次數不增、同頁再 ON 第二次複製；新 PID 由 App 自行載入 |
| API35 遊戲 | 0.13.3、精確157.0：原四組 OFF、App 先開自行載入、水果詳情複製與獨立被動讀回、OFF 次數不增、同頁再 ON 第二次複製；正常重啟新 PID 自行重綁，再進水果詳情完成複製 |

兩台現有帳號都只有一筆未派水果，其他三筆是點擊即領取的完成項目，因此不代領取，也無法驗左右換卡與花苗。手機、其他遊戲版本、高速滑動、跨帳號及耐久尚未驗證。0.13.0 API32、0.13.3 API35 另以被動讀取端確認水果剪貼簿格式及相同內容指紋；該端在產品複製後才安裝，不提供載入或複製能力。

兩台產品執行前均排除控制中心 package、額外顯示模組與研究 clipboard APK；API35 另移除既有兩個純研究 CPU probe。App 載入時 adbd 為 shell UID2000，ADB 只操作 UI／正常安裝及事後讀取證據，未執行手動注入。API35 事後用 adb root 讀回報，重啟測試前恢復 UID2000。兩輪 API35 程序回報均為同一候選 build，新程序重新計數、無失敗；測後正常關閉並恢復 OFF。

本輪 UIAutomator 在 API35 dump 已產出 XML 後的 Shutdown thread 發生 SIGSEGV；Game 與 App 繼續運作。保留私有原件，不把測試工具結束失敗轉記為產品成功或遊戲 crash。

來源選擇性參考 `pikmin-control-center` 的 `8abb7ee` carousel 判定，未整批移植核心或其他自動化。自有 JNI helper 先在獨立研究程式驗能力，再封裝進原 APK payload。
